# 数据定义

票号与原始编号均为字符串，保留前导零。称重支持 kg、公斤与 t，统一为 kg，单价为 CNY/kg。
毛重与皮重按票号和版本配对，品类、单价、扣杂率与更正目标必须一致。计价重量=(毛重−皮重)×(1−扣杂率)，先量化到0.001kg，再乘单价，金额四舍五入到0.01CNY。
每票第一版不填写 replaces。后续版本只能替代当前生效版，分支或缺基版整票阻断结算。已支付额为各版本中最大累计已付值，待付=最终应付−累计已付；负待付表示待收回。
同编号同原值仅计一次；同编号不同原值全部隔离。空文件、全空行和仅表头分别报错。原始输入计数包括空行及重复表头，对账会分别解释。
归档封存保存逐版证据、隔离原因和运行摘要，非支付执行系统。数据使用虚构编号，不连接实际支付渠道。

## 召回处置证据

召回使用三份独立 CSV，均为字符串编号并保留前导零，时间字段必须带 UTC 偏移：

- `recall_inspections.csv`：抽检报告。`batch_no` 来源批、`voyage_no` 船次、`report_version` 报告版本、`replaces` 替代版本（首版留空）、`verdict` 仅 `不合格/合格`。同一来源批按更正链选唯一生效版，替代目标必须等于当前生效版，否则整批阻断。
- `recall_sales.csv`：成交记录。一票可多行（多买家），`sold_kg` 按票求和；`batch_no` 在抽检证据中不存在即来源批追不到。
- `recall_destinations.csv`：去向核清。`trace_status` 仅 `已核清/失联`，`recalled_kg` 为已召回货量；票级待召回=成交合计−已召回合计。

票级处置结果固定三档：`召回`、`暂缓召回`、`免召回`。追不到来源批、报告链阻断、无去向证据、买家失联/对不上均为暂缓召回，不得判安全。来源批或生效版本变化时，已售票按新生效版重新裁决，仍在召回范围内。处置单 `order_no=RC-<证据指纹前12位>`，证据阻断未清为 `待发布`；发布按单据号幂等并记录 revision 与 UTC 发布时间。三份证据原始字节写入批次快照并随封存 zip 原样导出。
